# AlignLab｜继续后训练以后，怎样解释一项真实退化

**40 分钟模拟技术面。** 八段各 5 分钟。每段用约两分钟讲述、两分钟白板或读证据、一分钟回答追问。台词里的“项目”指有文件支持的工作；“我亲自复现、修改、判断”留给自己实际做过的部分。面试只有一分钟时，讲第一段的前两段，然后让对方挑一个问题深挖。首次排练用计时器，尤其给第六、七段留下十分钟。

## 00–05 分钟　为什么从一个已经会对话的模型出发

我想讲一个结果跟预期相反的项目。问题是，给已经能听指令的 Qwen2.5-7B-Instruct 再看一批高质量对话，然后告诉它同一问题下人们更喜欢哪种回答，在独立任务上会发生什么？工程上看，训练能跑完，模型能重新加载，也确实生成了回答。可是要求它按指令办事时，原始模型在 541 道题里整题通过 386 道，继续 SFT 后只有 323 道。后续 DPO 的主配置回到 333 道。拿今天这些结果交付，严格指令遵循这个目标我会保留原始模型。

这件事值得讲，是因为“回答流畅”和“把用户要求的每一件事都做对”差得很远。假设用户要求写一段有关阿根廷的介绍，并用 Markdown 突出至少三个部分。回答可能知识正确、读起来顺，但只加粗了两个位置。普通读者可能觉得答案挺好，依赖那个格式的下游程序却会判失败。项目把这种可检验的遵循能力单独测，也留下另一套偏好题，请读者在不知道模型身份的情况下比较回答。两个问题各自需要证据。

**现场展开**　在白板画原始 Instruct → 继续 SFT → DPO，在三个位置各画一条箭头连向同一个评测框。请对方任选一个节点，讲这个节点吃什么数据、更新什么、留下什么产物。原始模型也要真正生成一次，不能把模型卡上其他环境的数字写成自己的起点。最后在评测框里画两列，左列“规则可验证”，右列“读者判断”；先空着右列的结果。[正式逐模型汇总](evidence/formal_20261119/summary.json)

**面试官问，为什么不从预训练开始？** 答，目标是量化在现成指令模型上继续训练的增量。预训练主要学预测大规模文本的下一个 token，起点、数据和成本都与这个问题不同。这个项目要保留一个足够强的原始对照；如果微调伤害了已有能力，这样才能看得到。

## 05–10 分钟　从两种原始数据到可以训练的样本

SFT 的一条样本可以是一段多轮对话。程序按角色保留谁问谁答，学习其中的助手回答。偏好数据的一条样本要有同一个上下文，以及针对它的两种回答 chosen 和 rejected。它告诉训练程序这对回答的相对次序。把不相干问题的两个回答拼成一对，模型可能只是在区分话题，偏好标签就失去意义。

这个项目固定来源版本，从 UltraChat 的 20,000 条候选出发，最后留下 14,289 条训练对话和 3,650 条验证对话；UltraFeedback 从 10,000 条候选得到 7,400 对训练偏好和 1,775 对验证偏好。候选数、有效训练数和评测题数是三个不同分母。清洗时要验证结构和角色，检查真实分词长度，识别重复和相近提示，同组划分，并与锁定的评测提示做隔离。这样可以检查这次继续训练有没有混入留出的题；底座以往预训练时看过哪些网页，项目没有完整记录。

**现场展开**　在纸上写两条只差空格的提问，以及一条语义相近但措辞不同的提问。先演示字符串哈希怎样识别完全重复，再解释为什么还需标准化和近重复分组。把同组样本一条画到训练集、一条画到验证集，指出验证分数会回答一个过于容易的问题；再把整组移到同一侧。打开流水线，找到分组、划分、写证据的位置，说明为什么要记输入 revision 和最终文件哈希。[数据流水线](../src/alignlab/data/pipeline.py) · [规模与处理证据](evidence/stage_20261117/data_evidence.json)

**面试官问，偏好标签来自哪里，能等同于我们用户的偏好吗？** 答，标签来自所用公开偏好数据的构建过程。它是训练信号，并没有采样本产品的用户。要验证换到另一种偏好定义还能不能用，必须写清裁决准则，在独立提示上重新比较。模型学会复现某套标签，与目标读者觉得它更好，是两项实验。

## 10–15 分钟　给模型看完整对话，哪些位置算 loss

我用一句简单的话解释 SFT。模型每次看到前面的 token，预测下一个 token。训练时已经有标准助手回答，所以能从输出分布里取出真实下一个 token 的概率，计算负对数。概率越低，这一项罚得越重。用户提问还得完整出现在上下文里，否则模型压根不知道答什么；在这个项目里，计算监督目标要按模板和角色排除不计分的位置。把用户文字也一律当目标，会让优化器花力气模仿用户怎么提问。

举个手算例子。假设只有两个有效目标 token，模型分别给正确答案 0.8 和 0.2 的概率。平均交叉熵约为 0.916。把第二个概率提到 0.4，平均损失降到约 0.570。模型只是对这两个标准 token 更有把握，尚未证明它能完成新问题的全部要求。训练时前一个标准 token 可见，部署时前文里还有它自己生成的 token；第一处失误可能改变后面整段回答。

**现场展开**　画“用户内容 → 助手起始标记 → 答案 token A → B → 结束”的序列。画出预测 A 时最后能看见的位置，再画出预测 B 时能看见的位置。把上下文可见性和监督目标分两行。遇到特殊符号，回到实际模板产生的 labels 找证据；不同实现的边界可能不同。读标签审计和正式 SFT 配置，说明为什么 user 内容的监督掩码、padding 的处理和因果可见性分别要检查。最后讲一次反向传播和一步优化器更新的分工。[标签与参考模型审计](../src/alignlab/training/audit.py) · [正式 SFT 配置](../configs/gpu_20261118/formal_sft.yaml)

**面试官问，能不能只看 loss 选最后的模型？** 答，它能告诉我模型对验证参考文本的预测，但合法回答往往有很多种。部署时我关心模型生成的那一个回答是否遵循指令。所以需要在相同生成条件下真正生成，并把输出送入独立评测程序。本项目的退化恰好说明这一步不能省略。

## 15–20 分钟　单卡怎样训练，又怎样证明产物可恢复

7B 指模型的参数规模。全参训练通常还得为可训练权重存梯度和优化器状态。这里用 QLoRA，将大部分底座权重以 4 位 NF4 保存并冻结，在线性层旁边学习两组低秩矩阵。前向时两组矩阵的乘积给原线性变换加修正。秩 r 限制这条修正通路的维度；本次 r 为 16，LoRA alpha 为 32。低比特主要省底座存储，激活、计算临时张量和优化器仍占显存，所以参数少并不能推出任意长度和批大小都能塞进显存。

正式实验在单张 A800 80GB 上做。单次每卡一个样本，累积 16 个微批再更新一次，序列截断长度为 1,024。SFT 学习率为 0.0001，完成 893 个优化步骤。这个“步”数的是参数更新，不等同于读了 893 条数据。训练时有一个专门验证过的恢复点，程序实际从 checkpoint-100 重新接上。最后还要导出并重载模型做生成，把“训练目录写出来了”和“交付的模型能用”各验证一遍。

**现场展开**　先写普通线性层 y = Wx，再加上一项与 BAx 成正比的修正。用 W 为 4×3、秩为 1 的小例子，推 A 为 1×3、B 为 4×1，并把它们与输入相乘。这是教学尺寸。然后打开恢复证据，把 optimizer step、调度器进度和只含 adapter 权重的推理产物区分开。面试官如果只给一份 adapter，请说出还需拿哪些底座版本、配置与模板才能对照生成。[训练配置与实测](evidence/formal_20261119/training_evidence.json) · [实际恢复证据](evidence/formal_20261119/recovery_evidence.json)

**面试官问，显存占用能直接向别的显卡承诺吗？** 答，我先给出硬件、序列长度、微批和精度，再说明统计口径。框架记录的峰值已分配显存与整卡使用量有差别。换显卡、换内核或加长上下文都需要短试跑重新测。这个项目可陈述的是已用这套配置完成了完整训练和生成。

## 20–25 分钟　DPO 在比较哪四个数

SFT 之后，同一个问题有一个更受偏好的回答和一个较差回答。DPO 同时计算策略模型和冻结参考模型对这两个回答的条件 log probability。计算时要对回答 token 的对数概率求和，同一提示的上下文提供条件。先算策略模型给好、差回答的 log 概率差，再减去参考模型的同一个差。通俗讲，问的是策略相对它出发时，有没有更偏向这对里的好回答。

这里的参考是 SFT 阶段的模型。假设开始更新时，策略就等于参考，那么相对差是 0，标准 sigmoid DPO 损失是 ln 2，大约 0.693。假如之后策略的好减差为 −2，参考的好减差仍为 −4，相对差就是 +2。取 β=0.1，损失是 −log sigmoid(0.2)，约 0.598。注意，策略给好回答的整段概率仍可能更低；这个训练对的相对方向已经改善。这个算例只用来说明目标，拿它推不出真实偏好胜率。

**现场展开**　画两行两列，行是策略和参考，列是 chosen 和 rejected。在四个格子下面完成前面的减法，再让面试官把一行互换看符号怎样变。打开参考审计，解释为什么除了检查配置文件还要检查数值。起点一致时同一输入的输出应对齐；做一次探针更新后，参考必须保持固定，且这次探针不能污染正式训练。主 DPO 配置 β=0.1，学习率 0.000005，完成 462 步；另一个 β=0.05 的对照保留同一起点和预算。[参考模型说明](dpo_reference.md) · [DPO 配置](../configs/gpu_20261118/formal_dpo.yaml) · [β 对照](../configs/gpu_20261118/formal_dpo_beta005.yaml)

**面试官问，你为什么没有先做 PPO？** 答，这里已经有成对离线偏好数据，需要检验从同一个 SFT 起点再训练的增量。DPO 可以直接优化这个目标，不需要先训练一个在线采样策略。PPO 所需的采样、奖励设计与策略更新是另一条路线。若未来业务反馈只有在线交互才拿得到，问题和实验设计会随之改变。

## 25–30 分钟　四个数字如何变成一个可信判断

固定 541 个 IFEval 提示。严格整题的口径是该题的约束全过才算通过，一题满足两项、漏掉第三项，整题仍算失败。原始模型 386/541，71.35%；继续 SFT 为 323/541，59.70%；主 DPO 为 333/541，61.55%；β=0.05 为 334/541，61.74%。如果换成单项约束，分母变成 834，四者分别通过 659、568、587、592 项。报数前先说分母，别人才能复算。

同一批题由每个模型都答过，所以可以逐题比较。原始到 SFT，有 91 题从过变不过，也有 28 题反过来，净少 63 题，下降 11.65 个百分点。SFT 到主 DPO 则有 30 题改善、20 题退化，净多 10 题。按题做配对重采样，后者的 95% 区间约为 −0.74 至 +4.25 个百分点，跨过零。β 从 0.1 改成 0.05 净多一道，证据也不足以推断它稳定更优。单个训练种子还留下另一层不确定性。

**现场展开**　画一张 2×2 表。行是原始模型是否通过，列是 SFT 是否通过。填入都过 295、仅原始过 91、仅 SFT 过 28、都没过 127。请面试官任选一行一列，现场求出两个模型的分子和 541 的总数。再用两道虚拟题演示怎样重抽“题号”并把不同模型在该题的结果一起带走；若分别给每个模型抽题，会丢掉同一道题难度相同的信息。解释区间描述的是这组题的抽样不确定性，重复训练的波动还需多个种子去测。[严格与宽松结果、配对比较](evidence/formal_20261119/summary.json)

**面试官问，有没有生成偏好题的答案？** 答，每个条件还有固定 200 个偏好提示的生成。材料已经生成不等于有人裁过，独立人工盲评尚缺，所以当前没有可以投递的人类偏好胜率。规则评测只支持对所测指令遵循能力下结论。

## 30–35 分钟　模型为什么退化，哪些解释已经能排查

我会先拿一道题出来讲。ifeval:44 要求特定关键词以及至少三处 Markdown 高亮。SFT 的回答保留了关键词 Argentinian，但只用了两处高亮。另一道 ifeval:66 要求恰好五段并按指定分隔符排版，回答写成开场白加编号建议，格式检查就过不了。按同类约束看，高亮从 43/48 项通过降至 27/48。看到这些例子，我会先问几种能验证的问题：输出是否被硬截断？模型是否仍有足够长度完成格式？训练示范是否覆盖这种约束，而且自己遵守了它？

先查硬截断，因为它可以用逐题日志回答。91 道由过变不过的题，SFT 只有 5 道触及 2,048 个输出 token 上限；86 道未触及，其中 84 道两边都低于上限。这已经削弱“统一加大输出长度就能解释所有退化”的猜想。在两边都低于上限的 519 道里，原始过 369 道、SFT 过 312 道。这个子集是生成之后才看长度挑出来的，只作为排查；它不能告诉我们如果同一个模型允许生成更长，分数会变化多少。提前结束、样式偏好、学习率和训练数据都还可能有关。

**现场展开**　打开两组[逐题原始模型结果](evidence/formal_20261119/base_strict_cases.jsonl)及[SFT 结果](evidence/formal_20261119/sft_strict_cases.jsonl)，按同一题号对齐。先逐项说哪里满足、哪里失败，再读输出长度。然后在纸上画三列，“观察到的事实 / 被削弱的解释 / 可检验的下一步”。把 5/91 填进第一列，第二列写“硬触顶解释不了大多数翻转”，第三列写“查训练示范里的明确约束及回答合规率”。面试时留意别把第三列的假设讲成结论。[长度诊断](evidence/length_diagnostics_20261119/summary.json)

**面试官问，如何让下一次实验真的有学习价值？** 答，我会提前写清只改变一个因素。比如如果发现示范确实漏掉可验证要求，可以先在训练侧修订样本，保留相同起点、步数和生成条件，与原数据训练对照。如果样本太少，优先建立独立开发集或验证更小 SFT 学习率。已经看过的 IFEval 用来讲历史结果，后续选择配置需要开发集，最终确认再用未参与选择的题。

## 35–40 分钟　如何验收、交接，并诚实讲自己的贡献

到这里可以分清三件事。训练链路已有真实记录，SFT 和两个 DPO 配置都完成了。指令评测已经说明，继续 SFT 损害了这个起点的严格遵循表现，两个 DPO 都只收回了一部分。还有一个很值得做的验收是人工偏好：同一个提问，两边匿名显示真实回答，由人先看题目要求，再看事实、遗漏和可用性。能允许平局或无法判断，记录理由，再由程序根据隐藏映射聚合。若先偷看模型身份，再补标偏好的理由，就破坏了这项验收。

固定范围里项目已通过 85/100。剩余 15 分的整项验收包含真实盲评；写更多代码、补更多图都不能替代读者判断。工程依赖的边界我也会说清楚：分词、张量计算、量化和训练器有成熟框架；项目里的价值可以指到样本治理、标签和参考审计、断点恢复、统一生成、成对统计与失败归因。个人能自称亲手完成的工作，我会单列我自己运行的命令、检查的样本、改动的参数和独立解释过的失败。面试官愿意深挖哪一块，我就打开相应文件演示。

**现场展开**　模拟最后一道开放题：“现在必须发布一个模型，你选谁？”如果上线前唯一验收条件是严格指令遵循，我选原始 Instruct；若目标是特定领域的人类偏好，我先写偏好准则并做匿名裁决。若资源只够再做一次训练，我会说明单变量、开发指标和停止条件，保留没有收益的结果。最后合上讲稿，用一分钟说清“哪一步出现退化、哪个解释变弱、哪件事仍不知道”，把余下一分钟交给面试官追问。[固定验收](PROGRESS.md) · [盲评代码](../src/alignlab/evaluation/blind.py) · [项目交接](../HANDOFF.md)

**面试官问，最愿意在简历上写哪一句？** 答，在 Qwen2.5-7B-Instruct 上完成 QLoRA SFT 和离线偏好优化对照，在相同的 541 道独立指令题上，继续 SFT 的严格整题通过数从 386 降到 323；逐题配对定位 91 道退化，发现其中 86 道未触及生成上限。每个数字都可回到文件复算。等我亲手复算并讲清方法，再按自己的贡献调整主语。

### 你的第一遍独立接手

在项目根目录打开 PowerShell，以下步骤只读已提交的结果，Mac 也可直接在 GitHub 打开对应文件。先遮住右侧的 SFT 分数，在纸上用 91 和 28 推出它。再运行下面的命令；应看到每个版本的分子、分母和百分比。最后从第七段任选一道真实题，写下“我观察到……我仍不知道……我会用……来验证”。请把自己的判断和项目现有分析分别保存。

~~~powershell
$m = (Get-Content docs/evidence/formal_20261119/summary.json -Raw | ConvertFrom-Json).models
$m.psobject.Properties | ForEach-Object {
    $s = $_.Value.strict
    '{0,-12} {1}/{2} {3:P2}' -f $_.Name, $s.passed_prompts, $s.n_prompts, $s.prompt_level
}
~~~
