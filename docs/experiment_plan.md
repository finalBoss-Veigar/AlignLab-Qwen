# 实验计划：不预设提升

2026-11-19执行协议已冻结：单卡A800 80GB，清洗后的SFT训练14289/验证3650，偏好训练7400/验证1775；两阶段各1 epoch、seed42。主比较原始Instruct→SFT→DPO β=0.1。唯一追加因素为DPO β=0.05，其他训练参数、数据、SFT起点和生成条件相同；剩余时间少于3小时则不启动该扩展，并记录未运行。没有按测试集结果选择β；单训练种子限制须保留。

真实结果更新到README和`docs/evidence/formal_20261119/summary.json`。下面的候选列表是历史设计范围，并非本轮全部执行的实验；旧空表不能覆盖新的实际证据。

研究问题：在资源有限时，Qwen2.5-7B-Instruct 的继续 SFT 与 DPO 是否改善英语指令遵循与回答偏好？清洗和回答长度是否解释差异？这是离线个人实践。

主实验固定 7B：原始 Instruct、继续 SFT、相同 SFT 终点+DPO。调试阶段独立标记 1.5B，所有结果按模型规模分开。7B 目标 Linux 单卡24GB QLoRA；DPO 是否装得下待实测。本机6GB只完成开发验收。磁盘还需预留原始权重、合并权重、adapter、优化器和数据空间；不能只按4-bit参数大小估算。

初始候选：长度1024、微批1、rank16、SFT lr=1e-4、DPO lr=5e-6、β=0.1、seed42、无 packing。实际有效 batch = 微批 × 梯度累积 × GPU 数，逐run记录。先小步检查标签、数值、参考一致性、峰值显存和断点恢复，再确定正式预算。混合精度按设备支持选择并记录，OOM变更需新配置和新run。

数据来源：UltraChat train_sft，清洗后目标最多约20000条；UltraFeedback train_prefs，目标最多约10000对。不足不补抽。原始/非法/质量/重复/污染/长度/划分/采样的实际数量来自 manifest。两阶段允许复用合法训练来源，但 SFT 和 DPO 的训练数据均不能命中任意验证或官方评测组。官方 test 与 IFEval 不用于选参；IFEval 的 Hugging Face split 虽叫 train，仍整体作为评测。

先完成主对照，预算允许再单因素：必要合法性过滤 vs 增加质量/长度过滤（两组都执行防泄漏及安全长度上限）；rank8/16/32；β0.05/0.1/0.2。禁止一次笛卡尔积。各条件尽量保持总更新步数、token预算、数据、解码一致，并列出确实改变的因素。核心结论再复验种子42/43/44，报告均值、波动、失败run与预算差异。

## 2026-11-20 训练示范的列表格式核查

已观察到格式退化。先固定一个成本低的训练数据问题：如果用户明确要求编号或项目符号列表，紧邻的助手示范里能找到几行对应标记？同时读取冻结的 SFT train 和 validation，不使用 IFEval 答案筛选样本。按划分分别报告对话总数、相邻问答数、命中对话数，以及按两类要求分组的零行、一行、至少两行计数。

规则只识别脚本中预写的英语表达，过滤含否定、代码围栏和同时命中两类的提问。答复中的代码围栏不计数，编号只识别行首数字加点或右括号，项目符号只识别行首四种常见符号。多轮中同一对话可以数次入表；两行标记也可能重复编号或与问题无关。该检查看格式的可见线索，不能替代全文质量标注，不能估计所有指令的覆盖率。

先看命中量，再解释各桶。若训练示范中有多条零行记录，就回到原始对话核看上下文；若命中很少，就把覆盖不足作为该规则的局限，先构建独立开发题。任一结果都不足以直接过滤全部示范、启动重训或宣称修复模型。运行前固定源码和三项回归测试，聚合产物只包含计数与复现元数据。
